## Prepare input

Create a CSV with one row per physical fish and these columns:

`fish_id,specimen_id,capture_session,augmentation_parent,split,expert_grade,expert_reviewer,review_reference,mask_review_status,image_path,mask_path,camera,lighting,exposure,white_balance`

Use `B` or `C`; `train`, `validation`, or `test`; and `APPROVED` or `ADJUDICATED` for a reviewed single-fish mask. Paths may be absolute or relative to the CSV. Images and masks must match in dimensions; masks use >127 foreground and at least 500 fish pixels. `augmentation_parent` identifies the original source even when a row is not augmented. Record real exposure and white-balance settings, rather than inventing values. Labels, mask approval and metadata are declarations, so independently verify the review records and lineage. One fish per row avoids counting augmented views as independent fish. The script rejects shared specimen, capture session, augmentation parent or exact image bytes across splits; this is not proof that undisclosed related samples or near duplicates are independent. Disclose any exposures of validation/test fish in either model's prior training.

Optionally add `model2_prediction`, `model2_checkpoint`, and `model2_independence_note`; each aligned B/C prediction must name its checkpoint and provide its independence rationale. Missing or abstaining predictions are excluded from this baseline, and candidate metrics are also reported on the same covered subset. These notes require external verification. A Model 2 output is not supplied by this scaffold and a combined model is not implemented.

## Reproduction and outputs

From the repository root, after preparing and reviewing the manifest and pre-registering a split and procedure:

```powershell
py -m src.evaluation.bc_color_experiment --manifest path/to/reviewed_fish.csv --config configs/bc_color_experiment.json --output path/to/new_validation_results
```

`experiment.json` records seed, selected feature names, proxy thresholds, input/mask hashes, declared provenance, sample counts and results. `report.md` includes per-class precision/recall, macro F1 and B/C confusion; `false_predictions.csv` lists errors; `validation_distributions.png` shows individual values and overlap. Lighting-stratified descriptive results include sample sizes. Metadata record exposure and white balance but do not implement a calibrated correction or remove confounding. The fixed features and `ColorSettings` are defined in advance; a scaler and logistic regression are fitted only on training rows. The default command does not evaluate the test split. Run the separately authorized, locked final evaluation only after reviewing and freezing the procedure:

```powershell
py -m src.evaluation.bc_color_experiment --manifest path/to/reviewed_fish.csv --config configs/bc_color_experiment.json --output path/to/new_locked_test_results --evaluate-test
```

The flag does not technically prevent repeated inspection; researchers must enforce one-time test access and document all prior model/dataset exposure. Fresh output directories prevent accidental overwrites. The script checks minimum feasibility (both classes in train and validation), not statistical power, representativeness, camera/lighting balance, or label authenticity. Small-subgroup metrics are descriptive and should not support scientific claims. Use the existing offline masked color extractor, whose proxy thresholds are not grade thresholds; yellow/brown/dark and highlight components are sensitive to exposure and lighting. No production grading policy or model weights are changed.
