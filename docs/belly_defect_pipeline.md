# Belly-observation ingestion and review export

The pipeline imports linked image, fish-instance, specimen and reviewer records. It validates geometry, source provenance, label values and version consistency; checks disagreements; generates deterministic capture/specimen/fish-grouped splits; and exports a review artifact. It performs no model training, publishes nothing, and does not certify expert identity, consent, labels, adequacy or rubric approval.

The existing segmentation dataset uses image IDs and part annotations; `src/preprocessing/dataset_utils.py` already represents image/instance/specimen links. The new format is **COCO-inspired**, not strict COCO: it retains separate `images`, `fish_instances`, and `annotations` so an image can contain multiple fish. It does not reinterpret the existing A/B/C part masks as belly-defect labels. The [dummy example](belly_defect_dummy_batch.json) is synthetic only; its image path intentionally does not exist and its placeholder date and identities are not evidence. It illustrates the schema and cannot be imported without generating an appropriate synthetic image.

## Manifest contract

The root JSON has `schema_version: "belly-batch-v1"`, optional `rubric_approval_reference`, optional `synthetic_only`, and the three arrays below. IDs are nonempty strings and references must resolve within the batch. Treat IDs as opaque and case-sensitive; use consistent identifiers across all images and augmented views. The association has the same role as the existing `image_id`/`instance_id`/`specimen_id` mapping, plus a persistent `fish_id` and capture group.

- Each image has unique `id`, local `file_name` (relative to the manifest or absolute), integer `width` and `height` matching the actual readable image, `capture_group_id`, `source_reference`, and `consent_reference`. Duplicate image IDs or identical image bytes under different IDs are rejected. Consent references are asserted, not verified.
- Each fish instance has unique `id`, existing `image_id`, persistent `fish_id`, and physical `specimen_id`. Multiple fish can be linked to one image, and multiple images can link to one specimen. Every image must link to at least one fish and every fish instance to at least one observation. A fish cannot map to multiple specimen IDs.
- Each observation has unique `id`, `fish_instance_id`, `finding_id`, `reviewer_id`, ISO calendar `reviewed_at`, `consultation_reference`, exact `rubric_id`, `review_status` (`pending`, `reviewed`, `adjudicated`), `presence` (`yes`, `no`, `uncertain`, `unknown`), `type` (`hole`, `tear`, `exposed_tissue`, `acceptable_processed_opening`, `other`, `uncertain`, `unknown`), `severity` (`none`, `minor`, `moderate`, `severe`, `uncertain`, `unknown`), `visibility` (`visible`, `partially_visible`, `occluded`, `out_of_frame`, `image_quality_insufficient`, `uncertain`, `unknown`), and `grade_effect` (`no_effect`, `downgrade`, `reject`, `unassessable`, `pending`, `unknown`). A box is `[x_min,y_min,x_max,y_max]` or a polygon is `[[x,y],...]` in original-frame pixels; specify at most one. Positive defects require geometry. Unknown is preserved rather than converted to a negative label.

Different reviewer labels for the same fish instance and finding are rejected unless exactly one separate adjudication record exists. Original reviews remain in the source manifest. Geometry and label consistency are mechanically checked, but neither review independence nor expert qualifications can be established by software. The rubric is still a draft; a claimed approval reference must be checked against actual signed records. A `reviewed_at` value records an actual observation or review date, not a fabricated consultation.

## Run and review

```powershell
py -m src.preprocessing.belly_defect_dataset --manifest path/to/private_batch.json --private-output path/to/new_private_audit --export-output path/to/new_review_export --rubric tamban-belly-draft-v0.1 --seed 42 --preview
```

Both output folders must be new, separate and non-nested. The private audit contains original image IDs, image hashes, seed, input manifest location, group split assignment, counts and warnings. `--preview` writes private overlays without changing raw images. The separate `observations.json` is a pseudonymous, COCO-inspired review artifact containing split, geometry and labels, without source paths, source references, reviewer names or consent references. It does not copy images. Deterministic hashed IDs are **not anonymization**: they may be guessed or linked. Never publish the artifact or images until the team verifies consent, licenses, disclosure risks and expert approval. Preserve the original protected manifest and source images separately.

Splits connect images transitively by capture group, fish ID and specimen ID and keep each connected component together; seed 42 gives repeatable assignments. The allocator is a size-based proposal, not a stratified design, and can yield empty or imbalanced partitions. Visually similar images, missing shared IDs, misleading IDs, unrecorded prior model exposure or untracked augmentations can still leak; manually verify lineage and augmentations before study use. Fewer than five normal-opening or severe-positive observations are flagged as inventory warnings, not claims of statistical power. Empty train/validation/test partitions are also flagged.

No confirmed belly-defect labels were identified in the inspected project data. Real annotation counts, approved rubric, consent records and independently reviewed labels remain outstanding. Every generated artifact is review-only and cannot authorize training or grade-changing behavior.
